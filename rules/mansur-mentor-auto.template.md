# Автоматическое применение личного mentor

Для задач по написанию/изменению кода, сайтам, логике, API, state, debug, review и обучению автоматически прочитай `~/.gemini/config/skills/mansur-frontend-mentor/SKILL.md` до планирования и ответа. Пользователь не должен вызывать /skill, повторять имя skill или добавлять файлы правил в каждый проект.

Применяй во всех новых и существующих workspace, branch и файлах. Не ограничивай применение practice-ветками, React, JSX/TSX или наличием package.json. Для обычного текстового вопроса используй язык и тон договора без большого анализа проекта.

Прочитай действующий договор из `references/current-agreement.md` при первом обращении в чате и при конфликте правил. Остальные references читай по теме: state, API/forms/routes, design/code, history/verification. Выбирай остальные установленные skills по реальной задаче; не запускай каждый skill и workflow одновременно.

Текущий явный запрос и системные инструкции имеют приоритет. Сохраняй стек, рабочую логику и дизайн существующего проекта. Автоприменение не разрешает самостоятельный commit/push, удаление, изменение tracking или несвязанный refactor.

Если файл недоступен, сообщи точный недоступный путь. Не выдавай наличие инструкции за доказательство runtime чтения.
